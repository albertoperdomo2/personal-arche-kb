# Qwen3.6 AgentX clean U0.85 offload matrix

## Executive summary

This report asks whether adding a 64 GiB CPU KV tier, then an NVMe or CephFS secondary tier, improves a single Qwen3.6-35B-A3B replica under the same AgentX workload. The four runs used TP=2 on two H100s, `gpu-memory-utilization=0.85`, 200 GiB `/dev/shm`, C=32, seed 42, the same node, the same vLLM v0.23.0 image digest, and a 1,800-second send window.

The measured staircase is clear: CPU offload raised successful request throughput from **1.085 to 1.426 req/s** (+31.4%), while NVMe reached **1.518 req/s** (+40.0%). CephFS reached **1.518 req/s**, effectively identical to NVMe in this single run. NVMe and CephFS also completed the same 52 AgentX sessions and had nearly identical prompt-source composition, KV-transfer rates, and storage byte throughput.

The mechanism is reduced recomputation: local compute supplied 63.2% of baseline prompt tokens, 21.9% with CPU offload, and only 10.6% / 10.6% with NVMe / CephFS. The two secondary tiers therefore realized the same reuse pattern in this workload.

## Validity verdict — **Valid for a controlled single-run observation**

The matrix is configuration-matched and operationally clean: no pod restarts, CUDA OOMs, tracebacks, model-server errors, offload store refusals, or Ceph stalls were found. Request error rates were at most 0.072% and consisted of one or two isolated `ServerDisconnectedError` client records; CephFS had zero request errors and zero grace cancellations. The errors occurred during profiling, but did not coincide with a retained server-side fatal error.

The scope is deliberately narrow. There is one repetition per cell, the fixed-duration workload reaches different later trace segments as faster cells complete more sessions, and the NVMe host path had `cleanup: false`; its cold-cache state is therefore not proven even though filesystem usage was only 0.70% at metric-window start. Treat the ordering as the result of these four runs, not as a confidence-bounded population estimate or a proof that CephFS and NVMe are generally equivalent.

## Main takeaways

- **Measured:** CPU 64 GiB improved request throughput by 31.4% and reduced mean TTFT by 62.1% versus no offload.
- **Measured:** NVMe added 6.5% request throughput over CPU-only and reduced mean TTFT by 30.2%.
- **Measured:** CephFS and NVMe were indistinguishable at headline scale: request throughput differed by 0.003%, output-token throughput by 0.10%, and completed sessions did not differ.
- **Measured:** NVMe and CephFS carried almost the same storage traffic: 295.2/228.1 MiB/s read/write for NVMe and 291.9/227.5 MiB/s for the Ceph data pool.
- **Measured:** GPU KV-cache occupancy was highest without offload (mean 46.8%, peak 93.4%) and lower with NVMe/CephFS (mean about 32%, peak 60–65%).
- **Inference:** The secondary-tier gain is associated with a shift from local recomputation toward HBM hits and external KV loads. Temporal correlation and matched storage traffic support this mechanism, but a single matrix does not prove medium-level causality.
- **Limitation:** Ceph pool/MDS operation latency was unavailable. Cluster health stayed `HEALTH_WARN` because of `MON_DISK_LOW`, while the CephFilesystem remained `Ready`; no in-window slow-op or stall evidence was found.

$$
S_s = \frac{\sum_t r_{s,t}}{\sum_k\sum_t r_{k,t}},
$$

## Conclusions

### What the data establishes

For this controlled U=0.85, C=32 AgentX run, CPU KV offload is materially better than no offload, and either secondary tier is better than CPU-only. NVMe and CephFS produced the same realized reuse pattern and essentially the same client outcome. The equality is supported across throughput, TTFT, E2E latency, session completion, prompt-token sources, GPU KV occupancy, KV-transfer rates, and storage byte rates—not just one headline number.

### What remains uncertain

One run per cell cannot quantify variance. The fixed-duration replay processes more sessions in faster cells, NVMe cold-start cleaning was not proven, and Ceph operation-latency telemetry is absent. The data therefore supports “equal in this run,” not general NVMe/CephFS equivalence.

### Smallest next experiment

Repeat the four cells at least three times with explicit secondary-tier cleaning before every repetition, randomized cell order, and the same seed plus two additional seeds. Preserve the 15-second archive cadence, add NVMe await/queue depth and CephFS client/MDS/OSD latency, and record exact tier-resident bytes at start and end. A C=64 pressure step should follow only after replication; it will test whether the current 15–23% NVMe busy range and CephFS operation rate still leave headroom.
