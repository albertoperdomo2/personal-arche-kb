# Executive summary

This is a 30-minute AIPerf AgentX run at fixed concurrency 64 against two H100-backed replicas (TP=2). The deployment used CPU KV offloading with a CephFS secondary tier. The run is useful for end-to-end and scheduler-pressure analysis, but the requested external-tier retrieval telemetry is **not present** in the artifact export: every `kv_offload_tiering_lookup_async_*` query returned an empty Prometheus result. Empty is reported as **N/A**, never as zero.

The client profile shows substantial queueing and long tails (request-latency P50 14.77 s, P90 34.73 s, P99 83.95 s; TTFT P50 7.37 s, P90 16.54 s, P99 30.09 s). Server waiting requests reached 34 and request-queue time reached 13,954.7 s in the exported histogram summary. These are real scheduler/client observations, but they cannot be attributed specifically to CephFS retrieval without the tiering lookup series.

**Verdict:** end-to-end evidence is valid; the external-tier mechanism verdict is **inconclusive**. Re-run after confirming the tiering histogram is scraped and non-empty.

## Requested external-tier telemetry

The correct request-visible metrics are the deferred secondary-tier lookup delay, not CPU↔GPU DMA. `p50/p90/p99` are histogram quantiles; `mean` is delay-seconds divided by delay-count; blocked requests is average concurrent stalled requests; stall rate is lookup-event rate; overflow is delay above the 10-second histogram ceiling. A non-zero overflow makes P99 a lower bound. This run returned no samples:

| Metric | Prometheus series | Samples | Status |
|---|---:|---:|---|
| `kv_offload_tiering_lookup_async_p50_seconds_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_p90_seconds_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_p99_seconds_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_mean_seconds_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_blocked_requests_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_stall_rate_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |
| `kv_offload_tiering_lookup_async_overflow_rate_by_engine` | 0 | 0 | Unavailable (empty Prometheus result) |

There is no collected metric that separates pure CephFS I/O from queueing/scheduling inside the asynchronous lookup path. The end-to-end lookup delay would be the correct request-facing measure once exported. `kv_offload_transfer_mean_seconds_by_engine` is also empty here and, when present, is CUDA DMA time—not external fetch time.
