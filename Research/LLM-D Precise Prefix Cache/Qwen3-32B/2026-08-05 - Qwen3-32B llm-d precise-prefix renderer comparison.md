# 2026-08-05 - Qwen3-32B llm-d precise-prefix renderer comparison

## Executive summary

This compares two llm-d precise-prefix-cache deployments for Qwen/Qwen3-32B under the same Guidellm workload: the vLLM model pods expose the render endpoint, while the baseline uses three separate CPU renderer pods. Both use the main branch, eight TP2 model replicas, H200 GPUs, gpu-memory-utilization 0.95, a 1,200-token prompt, a 1,000-token generation, and the same 16 Poisson target rates (3–60 RPS).

The result is a near tie at the useful throughput knee. Three CPU renderers reach the highest successful-request rate, 6.03 requests/s at target 20 RPS versus 5.87 requests/s for the vLLM-render topology (+2.8%), and 49.76 versus 48.39 total tokens/s (+2.8%). The vLLM-render topology has lower TTFT P95 at that point (120.4 ms versus 138.7 ms). Neither deployment sustains the offered load: at target 60 RPS only 7.47% and 7.07% of requests complete successfully, with the remainder incomplete.

The prefix-cache mechanism is active: the hit ratio rises from zero during warm-up to approximately 99.4% and remains there. kv_offload transfer series are empty, as expected for a renderer-placement experiment rather than a KV-tier offload experiment.

## Validity verdict: Conditionally valid

The paired comparison is valid through the common throughput knee. It is conditional because this is one repetition, the large raw Guidellm output JSON was truncated during MLflow collection, and exact Git commit SHAs were not recorded. The complete generated report artifacts and Prometheus summaries are present, and all plotted per-rate values below come from those report artifacts.

## Main takeaways

- Measured: Three CPU renderers win peak successful-request throughput by 2.8% at target 20 RPS, a small single-run difference.
- Measured: vLLM-render has the lower TTFT P95 at the knee and avoids the CPU-renderer run high-rate TTFT-tail excursion.
- Measured: Both runs saturate well below offered load; at 60 RPS successful completion is 7.47% (vLLM render) and 7.07% (CPU render).
- Measured: Prefix-cache hit ratio warms to approximately 99.4% in both runs.
- Inference: Renderer placement is not the bottleneck at the useful knee; model-serving capacity and scheduler saturation dominate.
- Limitation: Pin and record exact branch SHAs before treating the small throughput gap as a regression.
