# 2026-08-05 - Qwen3-32B llm-d precise-prefix renderer comparison

## Executive summary

This compares two llm-d precise-prefix-cache deployments for Qwen3-32B. The model-serving configuration is held constant: eight TP2 H200 replicas, vLLM image digest unchanged, and gpu-memory-utilization 0.95. The tested difference is renderer placement:

- **vLLM render endpoint:** the render endpoint is served by the vLLM model pods.
- **Three CPU renderers:** three separate non-GPU vllm-render pods tokenize and render requests before routing to the model pods.

At the useful throughput knee (target 20 RPS), the CPU-renderer deployment reaches 6.03 successful requests/s and 49.58 k tok/s total throughput. The vLLM-render deployment reaches 5.87 successful requests/s and 48.21 k tok/s. The difference is 2.8% in one repetition. vLLM-render has the lower TTFT P95 at that point (120.4 ms versus 138.7 ms). Both deployments saturate above the knee; at target 60 RPS, successful completion is below 8% and incomplete requests dominate.

These results show near parity, not a categorical renderer winner. Exact llm-d commit SHAs were not preserved in the MLflow metadata, so the small throughput difference requires pinned-commit repetitions before it is treated as a real regression.

## Guidellm workload

Guidellm used the OpenAI HTTP backend with a Poisson arrival profile. Each target-rate phase ran for 30 seconds. The target rates were 3, 10, 15, 20, 22, 25, 30, 35, 40, 43, 46, 49, 52, 55, 57, and 60 RPS. The synthetic request contained 1,200 prompt tokens and requested 1,000 output tokens. Prefix reuse used one 100%-weighted bucket with 150 possible prefixes, each 6,000 tokens. The run plan enabled pre-warmup at 15 RPS for 50 seconds.

Because the prefix is 6,000 tokens, prompt-token throughput is much larger than output-token throughput. The report follows Benchflow's implementation: it plots the benchmark's successful prompt, output, and total token-rate metrics and divides them by 1,000 for **k tok/s**. The total series is the source benchmark total metric, not a second independently aggregated request series.
