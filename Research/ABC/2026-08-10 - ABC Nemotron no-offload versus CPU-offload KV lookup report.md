# Executive summary

This ABC comparison asks whether CPU KV offloading changes request-visible lookup behavior for Nemotron Ultra. The control is the no-offload run; the treatment uses `TieringOffloadingSpec` with a 256 GiB CPU tier. Both used one H100 replica, TP8, GPU memory utilization 0.8, max model length 131,072, concurrency 32, and a 30-minute AIPerf AgentX workload.

The CPU run has a populated **synchronous KV lookup P99** series, ending at about 31.5 ms. The no-offload run has no offload lookup series, as expected. The requested external-secondary `kv_offload_tiering_lookup_async_*` series are not populated in either artifact, so this report does **not** claim an NVMe/CephFS retrieval latency.

## Validity verdict

**Conditionally valid.** Workload shape and primary topology match, but the runtime images differ (`vllm-openai:v0.26.0` versus `vllm-openai:nightly`). The lookup result is useful as a mechanism signal, but the end-to-end difference cannot be attributed to offloading alone until the image is held constant.

## Main takeaways

- CPU offload exported `kv_offload_lookup_sync_p99_seconds_by_engine`; the no-offload control exported none.
- CPU lookup P99 is finite after warm-up and settles around 30–33 ms; early `NaN` samples are omitted, not converted to zero.
- CPU KV movement is active: transfer bandwidth and `kv_offload_total_bytes/time` are present. These are CPU↔GPU signals, not external-storage fetch time.
- Async tiering lookup P50/P90/P99, mean, blocked, stall, and overflow are unavailable in both artifacts.
