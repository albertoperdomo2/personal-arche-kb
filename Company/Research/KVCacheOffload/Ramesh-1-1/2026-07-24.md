## Part 2: Innovation Work - Activity-Based KV Cache Offloading (~42 min)

### Core Research Direction

**Project Name:** Activity-Based KV Cache Offloading (tentative: ABC or ABS)

**Hypothesis:** Time series forecasting can predict which KV cache blocks will be needed, enabling preemptive data movement from disk to CPU/GPU memory.

### Key Concepts

#### The 80/20 Rule Applied to KV Cache
- ~20% of KV cache data is accessed ~80% of the time
- If we can predict which 20% will be "hot," we can pre-load it to fast storage
- Results in: massive latency reduction (millis → micros) while maintaining large storage capacity

#### Architecture
```
Disk (SE filesystem) → CPU RAM → GPU Memory
   (compressed)      (decompressed, predicted hot data)
```

**Dual Advantage:**
1. Compress everything on disk (3-5x space savings)
2. Decompress only predicted "hot" 20% to CPU RAM
3. Benchmarking never sees compression or disk latency
4. Data always read from CPU tier → microsecond latency

### Time Series Forecasting Model

**Input Variables (Multivariate Time Series):**
- KV block eviction events (LRU events)
- Timing of evictions
- Size of KV blocks
- Reuse patterns
- Eviction frequency

**Output:**
- Classification: Hot/Coldest categories
- Forecast window: 5 seconds to 1 hour (configurable)

**Model Options:**
- **Lightweight (Phase 1):** XGBoost (leverages existing llm-d infrastructure)
- **Advanced (Phase 2):** LSTM, CNN-time-series, or Transformer models
- Training: Can train on GPUs during off-peak hours, deploy lightweight model for inference
